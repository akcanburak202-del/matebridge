# Protocol golden vectors

One file per message example: `<message_name>[_variant].hex`. Each file is a complete frame (5-byte header + payload), lowercase hex, whitespace ignored, `#` starts a comment. Every data line carries a comment `<type> <field> = <value>` naming the field and its value.

Files are generated by `gen.py` (the reference encoder): `python3 protocol/fixtures/gen.py --write` regenerates them, and `python3 protocol/fixtures/gen.py --check` fails if any file is stale. Exactly one of the two is required. Any other argument (including none) exits non-zero without writing anything. Layouts are defined in `docs/PROTOCOL.md`; if the script and the document disagree, the document wins.

Both `host-mac` (Swift) and `client-android` (Kotlin) unit tests must:

1. decode every fixture and compare fields with the values in its comments (and `docs/PROTOCOL.md`);
2. encode those values and produce the identical bytes.

This is how Swift/Kotlin drift gets caught before it reaches the device. Only the orchestrator edits fixtures.
